# chrome 浏览器

## 我们将开发什么？

 Chrome 浏览器插件 md-wx-chrome-plugin， 其核心功能是，在浏览英文网页时，一键提取文章核心内容，调用 AI 大模型进行翻译，并将翻译结果以 Markdown 格式优雅地呈现出来，支持一键复制粘贴到微信公众号。

## 文档先行：AI 辅助项目规划与设计

从零开始开发一个 Chrome 浏览器插件。
我们将再次采用“文档先行”的开发策略，在编写任何代码之前，首先与 AI 协作，明确项目的所有关键文档。

五个关键文档

1. 需求分析文档
2. 技术架构文档
3. 页面布局设计
4. 任务拆分文档
  把大功能拆成一个个可执行的小任务清单，标明顺序和依赖，方便 AI 或团队逐步实施、逐步验证。
5. 项目规则文档
  项目规则文档是给 AI 定"行为准则"的，规定代码风格、技术栈、命名规范等约束，让它干活不跑偏。

## AI 助手任务执行规范 

为确保开发过程的有序性和可控性，AI 助手必须严格遵循以下任务执行规范： 

### 任务范围控制 

- **严格按照任务拆分执行**: 必须严格按照 `docs/tasks.md` 中定义的任务范围执行，不得超出指定任务的边界。 
- **单一任务原则**: 每次只执行一个明确指定的任务（如"任务 1.1"、"任务 1.2"等），完成后等待用户确认再进行下一步。 
- **禁止自动扩展**: 不得基于技术架构文档或其他文档自行扩展任务范围，如果需要扩展需要通知用户确认。 

### 任务指令格式 

用户应使用以下格式明确指定任务： 

- **明确任务编号**: "请执行任务 X.X：[任务名称]" 
- **范围限制**: "只完成任务 X.X 中列出的具体任务，不要超出范围" 
- **停止指令**: "完成后等待我确认再进行下一步" 

### 执行验收标准 

- **任务完成确认**: 每个任务完成后，必须对照 `tasks.md` 中的验收标准进行自检。 
- **范围边界检查**: 确保所有创建的文件和代码都在指定任务范围内。 
- **等待用户确认**: 任务完成后使用 `finish` 工具总结完成情况，等待用户确认后再进行下一个任务。 

### 异常处理 

- **任务描述不清晰**: 如果任务描述不清晰，应先询问具体范围而不是自行决定。 
- **依赖关系处理**: 如果当前任务依赖其他未完成的任务，应明确指出依赖关系并等待用户指示。 
- **超出范围的代码**: 如果发现已创建超出任务范围的代码，应主动询问是否需要清理。

## 迭代优化：从 UI 重构到功能完善

### 优化 popup 页面 UI

我们成功实现了内容提取和基本页面展示的功能。当前，插件页面采用的是传统的 Popup 弹窗样式。但在实际使用中我们发现，翻译后的内容通常比较多，Popup 的固定高度显得捉襟见肘。因此，我们期望将其重构为从浏览器右侧滑出的侧边栏，并且高度能撑满整个页面，以提供更好的阅读体验。

你可能会有疑问，为什么不在最初就采用这种设计呢？在项目初期，我们可能对所有实现细节的把握还不够充分，需要先通过一个基本版本来验证核心功能。在迭代过程中发现体验上的不足，再借助 AI 的能力进行快速重构和优化。AI 的存在，让这种调整的成本变得非常低。

## 清理冗余代码

在完成功能重构和 UI 优化后，一个重要的步骤是清理项目中的冗余代码。之前 Popup 弹窗的实现逻辑依然存在于代码库中，为了保持代码的整洁和可维护性，我们需要将其移除。

在进行这类破坏性操作之前，强烈建议先通过 Git 提交一次当前的代码。这样，即使后续出现误删等问题，我们也可以轻松地回滚到之前的版本，确保代码安全。然后，我们让 AI 帮助我们完成代码清理工作。

```
现在已改为从右侧打开的侧边栏设计，请你将之前传统的弹窗形式的实现给移除掉，不要让代码冗余。

需要注意，如果当前侧边栏设计实现有引用的部分，不要删除，不要影响当前已实现的功能
```

目前已成功优化为 “侧边栏设计”，检查 `plugin/docs` 文档，按照最新的功能更新文档
