# REA

- AI时代， 软件已经死了吗？

## REA

Reverse Engineer Anything
逆向工程

没有源代码， 让Ai去研究一个软件， 搞清楚某个工程是怎么实现的。
再辅助你在自己的项目里做出来。 

图， 光看界面，根本看不出来， 现在呢， AI开始有工具往里去查了。 

## 逆向工程

正常开发， 程序员去写代码， 再把代码做成能安装的软件。

逆向工程是拿已经做好的软件， 倒过来再去研究， 里面有哪些模块，模块间
怎么配合， 一个功能到底是在哪里实现的， 就好像把电脑拆开， 没有图纸，
研究它怎么运转的。 

这事过去能做， 但很费功夫， 因为代码经过编译后， 注释，变量名都没了，
可以看到的是机器码， 你需要一点点去判断，这一段在算什么？数据从哪里来的，
结果交给了谁？

REA 把Hopper 这种专业工具， 直接接给AI, 让AI 可以去查函数， 追踪调用的关系，
读取线索，再根据这些线索， 辅助的去写出实现。

过去用vibe coding 去模仿一个软件， 需要说这里放一个按钮， 哪里需要去加菜单，点完之后，
要出现什么样的效果， 它可能做出一个还挺像的界面，但内部的逻辑，还是需要自己去重新设计。
有了REA, 它会去调查原来的工具是怎么工作的， 

你每天打开一个庞大的应用， 可能只用几个功能，为了几个功能， 就得按月付费。
如果AI能研究这些功能， 围绕你的需求，重新去做一个小的工具， 更好、更便宜的服务用户。

## 案例

这不是简单地仿写 Notion 的页面，而是研究一个看起来很普通、实际上涉及多个进程的功能——在 Notion 桌面端复制内容时，它是如何把文本、HTML 和富文本结构传递到系统剪贴板的？

先盯住一个功能，把它的执行路径弄清楚就够了。
