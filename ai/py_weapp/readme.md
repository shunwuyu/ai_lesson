## 5. UI 原型设计开发

正常情况下，如果是比较小的、网页项目，可以直接利用 AI 生成前端一把梭。

但是由于小程序开发比网页开发又更多的复杂度和兼容性的问题，建议我们先利用 AI 单独开发出一套 HTML 网页版的原型图，人工确认之后，再把原型图代码发给 AI，继续开发小程序的前端，会更稳定一些。

UI 原型设计工具的选择：你可以考虑使用如 Figma、Sketch 或 Adobe XD 这样的专业工具来创建 UI 原型。这些工具不仅提供了丰富的设计资源，还支持团队协作。
但是现在有了 AI，直接让 AI 生成 HTML 格式的原型即可，就类似于让 AI 开发一个纯前端的网站。
UI 原型设计开发是一个相对独立的任务，我们可以搞个 **赛马**，让不同的 AI 工具生成原型图，确保给每个工具提供相同的输入（比如功能需求、样式指南等）。然后选定最佳方案，再人工修改，直到获得一份纯前端的、满意的 UI 原型。

下面我们同时用 Claude Code、Codex 开发。

### 为什么要先做 HTML 原型，而不是直接开发小程序？

这是本节最核心的策略，值得专门理解一下。小程序开发比普通网页多了不少兼容性和复杂度，如果让 AI 一上来就直接写小程序，出了问题很难定位是「UI 设计问题」还是「小程序兼容问题」

所以教程采用了「分两步走」的策略：

第一步：用 AI 做纯 HTML 网页原型 → 人工确认 UI 满意
第二步：把确认好的原型代码发给 AI → 让 AI 照着开发小程序前端


好处是：
  HTML 原型在浏览器里就能看，改起来快、所见即所得
  把「设计 UI」和「实现小程序」两件事解耦，每一步都更可控
  原型确认后再开发，AI 有了明确参照，还原度更高、返工更少

什么是「赛马」开发？
我提到搞一个「赛马」，这是 AI 编程里很实用的一招：同一个任务，同时让多个 AI 工具/模型去做，再挑最好的那个。

| 要点 | 说明 |
| :--- | :--- |
| 相同输入 | 给每个工具完全一样的需求、风格要求，保证可比性 |
| 并行产出 | 让它们各自出一版初稿，再各给一次修改机会 |
| 择优组合 | 选出最满意的方案，甚至可以结合多个方案的优点 |


本节就同时用了 Claude Code 和 GitHub Copilot 两套工具赛马，最后取两者之长。AI 生成有随机性，单押一个不一定出好结果，赛马能显著提高拿到满意方案的概率。
