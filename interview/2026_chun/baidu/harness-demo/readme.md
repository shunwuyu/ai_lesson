Harness 是一种将 LLM 生成（让大模型当评委）、自动评测、择优筛选串联成闭环流水线的编排框架，让 LLM                      
  像被马具（harness）驾驭的马一样，在结构化流程中自动产出更高质量的结果。

这是一个 LLM-as-Judge + Best-of-N Sampling 组合的 Harness 模式。                                     
                                                                                                       
  核心思想：                                                                                           
  1. Best-of-N Sampling：并行生成多个候选代码，通过随机性覆盖更多可能性。                              
  2. LLM-as-Judge：用 LLM 充当自动化评分器，替代人工评测，实现闭环自优化。                             
  3. Harness（马具）抽象：将生成、评测、择优三阶段解耦为流水线，LLM 是"马",Harness                   
  是驾驭它的框架——只管调度流程，不关心具体任务是什么。

你写了一段"用 AI 写数组去重函数"的代码，但你不是直接让它写一次就完事，而是：
                                                                                                                                                                    
  让 AI 同时写 3 份代码（generateCandidates），然后再问一次 AI"这代码你给几分"（judge），最后挑分数最高的那份（pickBest）。                                         
   
  这就是 Harness 的核心思路——不把 LLM 当一次性工具用，而是给它套上"马具"（harness），牵着它走一套标准流程：先多生成几个候选，再自动打分评优，最后选最好的交差。     
                                         
  类比一下：你让三个厨师各做一道菜，然后让同一个人当评委尝一遍打分，端分最高的那盘上桌。你不需要自己尝，流程全自动化。

  所以 Harness 不是某种具体算法，而是一套**"生成 → 评测 → 择优"的编排模式**。你这份代码里的 generateCandidates、judge、evaluateAll、pickBest
  就是这个模式的标准零件，换个任务（写 SQL、写文案）一样能用，换汤不换药。
