# Agent 的对象存储方案： MinIO、RustFS、阿里云 OSS（对象存储服务）

AI Agentᵠ 在跑业务的时候，时时刻刻都要读写各种文件。

不管是上传的文档，还是 AI 自己生成的报表、图片视频

普通本地文件夹根本扛不住海量文件的生产场景。

所以要用对象存储（Object Storage）

叫“对象存储”是因为它不以目录树或磁盘块来管理数据，而是把每个文件当成一个带唯一 ID 和元数据的“对象”来存取。

比如这三类场景：

- 存放 RAGᵠ 知识库所有原始文件，给智能问答提供数据源
- 保存 Agent 自动运行产出的报表、图表、运行日志
- 统一存图片、音频、视频，支撑多模态 AI 处理任务

我们使用阿里云 OSS 作为对象存储。

我们本地存储是 目录-文件的真实树状组织方式：
而OSS对象存储底层是扁平化结构

每个 Object 对象包含三部分核心信息：唯一 Key 标识、文件二进制内容、自定义元数据：

## 多模态Agent 图解 

它支持图片、文本、语音、文档表格这类多模态输入，核心链路是**理解→规划→调用工具→生成回复**。
Agent 先统一解析不同模态的信息，再做任务拆解规划，按需调度能力组件：图像理解、文生图、ASR 语音转文字、TTS 语音合成、文档 OCR、联网搜索等工具。
最后输出也支持多形态，既能返回文本、图片，也能输出语音、文件图表。
亮点在于它不是简单串模型，而是把多模态感知、工具调用、任务编排封装成一个智能体，能承接跨模态的复杂业务，比如看图后按指令画图、语音提问后返回图文报告，适配很多端侧、智能助手场景。

图 2

这是一套基于多模态 Agent 的图片编辑业务链路。用户上传原图 + 编辑指令后，Agent 先把原图存到阿里云 OSS，拿到资源 URL，避免大图直接传给大模型带来的传输与上下文开销。接着 Agent 携带图片地址和用户指令调用多模态大模型（很多多模态模型支持直接传图片二进制，降带宽、控上下文。），由模型完成图片编辑。拿到生成结果后，Agent 再把新图回写到 OSS，最后把成品图 URL 返回给用户。
这个方案的亮点是用 OSS 做对象存储解耦，Agent 承担调度、资源管理的中间层角色，而不是单纯转发请求；同时统一管理原图和产出图，方便后续溯源、缓存和复用，适合图片生成、修图这类生产型业务。

图3

这是带 OSS 的多模态大模型调用链路。用户上传图片、音视频这类大文件，先存入 OSS 输入目录，拿到预签名 URL 传给大模型，避免二进制直传带来的带宽与超时问题。模型读取资源后完成推理，产出图文、音视频结果，再回写到 OSS 输出目录。最后用户凭预签名 URL 拉取结果。
亮点是把大文件读写交给对象存储，模型只传地址，降低接口负载；同时天然隔离输入输出目录，方便权限管控、资源溯源和异步任务调度，很适合图生视频这类大体积多模态生成业务。
